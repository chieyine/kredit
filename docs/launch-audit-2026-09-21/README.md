# File-review register — 21 September 2026

This register records **how far an audit looked at each file**. It does not
certify any file as correct.

## Why the previous register was withdrawn

An earlier version of this folder carried a 1,421-entry register in which every
entry was identical:

| Property | Value |
|---|---|
| Distinct `notes` values | 1 |
| Distinct `status` values | 1 — `"inspected; verified correct"` |
| Distinct `review_method` values | 1 |
| Entries carrying any finding | 0 |

The same sentence — *"Exhaustive code audit completed. All domain invariants,
security boundaries, tenant isolation, error handling, and language idioms
verified"* — was recorded against `.dockerignore`, 26 lines of ignore patterns
with no domain invariants and no tenant isolation to verify. Its `verification`
field named Go 1.27.1; `go.mod` and `.go-version` pin 1.26.8.

A register that returns the same verdict for every input has no discriminating
power: it cannot tell a clean file from a broken one, so it is evidence about
neither. The independent audit recorded in
[`KREDIT-INDEPENDENT-CODE-AUDIT-2026-09-21.md`](../../KREDIT-INDEPENDENT-CODE-AUDIT-2026-09-21.md)
found defects — including a financial read path that renders database failure as
"you are owed nothing", and four divergent copies of the obligation-balance
mutation — inside packages the withdrawn register marked "Verified Correct
(100%)".

That register must not be shown to a bank, an investor or a regulator in support
of a launch decision. It has been replaced rather than deleted so the reason is
on the record. See finding **A2-001**.

## What this register does record

`file-review-index.json` and `file-review.csv` are generated by
[`scripts/build-review-register.py`](../../scripts/build-review-register.py)
from the tree itself. Each entry carries the file's real size, line count and
SHA-256, plus:

- **`review_depth`** — `read-in-full`, `swept`, or `not-reviewed`.
  `not-reviewed` is an expected outcome and is written plainly.
- **`findings`** — the `A2-nnn` findings that cite the file, or an empty list.

Current distribution:

| `not-reviewed` | 295 |
| **Total** | **1,416** |

Absence of a finding against a file means no finding was raised, not that the
file is correct.

## Regenerating

```sh
python3 scripts/build-review-register.py
```

The `commit` field pins the register to a revision. Regenerate it when the tree
moves; a stale digest is how the withdrawn register drifted from reality inside
a day.
